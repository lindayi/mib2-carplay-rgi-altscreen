## Intentional integration changes

- **Installed authority:** only `/mnt/app/root/carplay-altscreen/state` supplies
  `ACTIVE`, `ARMED*`, `FORCE_START`, `run_id` and `IAP2_PROFILE`. No SD or `/tmp`
  fallback can arm the hook. Missing/nonregular/symlink markers fail closed;
  a late installed-state mount can still become available. The independent
  `fullchain_probe` authorization check retains the same installed-root contract.
  Logging stays volatile, without automatic SD fallback.
- **Receiver transport:** the latest universal AUG22 dynamic relocation discovery,
  private Type111 setup/teardown serialization, retained command lifetimes,
  bounded deferred cleanup, stock OMX decoding, Screen linearization, and matching
  H264/decoded SHM contracts are imported. The dynamic redirect and QNX process-name
  transformations previously generated by upstream's build script are applied
  directly to the source. Known-profile direct-proxy builds are not produced.
- **One UI owner:** `integration.h` disables native card/URL selection, showUI,
  stopUI, zoom and live viewArea commands. Native startup bootstrap submits only
  bounded, session-fenced forceKeyFrame requests. The local monitor performs tap
  ownership retry and consumer-requested keyframes, not native wheel scheduling,
  native stream-stall recovery, UI reassertion or context changes. Dormant upstream
  policy code is retained for provenance but cannot be enabled by a runtime file
  or environment variable. Build checks reject its URL/wheel/HMI-file strings in
  the resulting hook.
- **Geometry:** the mirror keeps the Type111 decoded source at 1440x542, with
  1:1 bottom clipping into the existing **1440x455** output. Internal offsets are
  zero; Java `AltScreenPlacement` alone moves displayable 3. There is no reading of
  upstream's HMI-layout or card-profile files and no position-triggered extra swap.
  Upstream's negotiated FULL/SMALL safe-area candidates remain declared; index 0
  is the default. This DSO never selects an index after negotiation. An existing
  outer RGI configuration interposer can still rewrite the initial viewArea.
- **Source validity:** accepted decoded frames additionally require active matching
  H264 writer/generation/cookie both before and after copying. Missing/inactive
  transport cannot make old decoded memory look like a fresh session.
- **QNX filesystem:** the new display-ownership snapshot and consumer keyframe
  request use `/ramdisk` atomic replacement. Replacement failure preserves the
  previous snapshot; there is no `/tmp` or flash publication fallback.
- **Existing runtime:** ready/base-ready/gate/log defaults match the local launcher;
  its environment overrides remain supported. Existing supervisor recovery and
  SI receiver ownership are retained. No native USB reset or receiver restart is
  introduced. The upstream `--stream-supervisor` executable mode is not included.
- **Artwork:** the embedded logo asset and assembler inclusion are omitted.
  The source-built mirror stays blank until actual decoded video, rather than
  importing artwork or reporting logo pixels as video readiness.
- **Presentation telemetry:** remove upstream's duplicate first-frame submit:
  one accepted source frame makes one ordinary interposable `eglSwapBuffers`
  call; only success advances `presented_frames`. Ready markers follow the first
  successful video swap. The explicit sink-test-grid diagnostic is separate from
  normal video mode. `PHASE=RUN` retains generation, decoded/presented frame counts
  and measured presentation FPS; current-stream teardown retains the exact
  `PHASE=DIRECT111_TAP_STOP stream=` marker, distinct from stale-stream teardown.
  The health reader's four H264 counters remain at offsets `0x18` through `0x24`.

## Required parent integration

1. Stage **both** `build/altscreen/libcarplay_altscreen.so` and
   `build/altscreen/carplay-alt111-mirror-display`; regenerate package manifests.
   Include this directory's license texts and notice. Do not stage `stubs/`,
   `objects/` or a toolchain library. Do not apply the old binary-only 30-fps
   patcher to these already source-built artifacts.
2. Preserve receiver preload order: local RGI hook before AltScreen hook.
   Preserve the isolated mirror-only mascot preload and existing settings,
   cards, VC panel and mascot `/ramdisk` contracts.
3. Forward `CMD_OEM_MAP_READY` (`0x0119`) to
   **`void altscreen_oem_map_ready(int ready)`**. The read-only export
   **`int alt_oem_map_startup_ready(void)`** is not the setter. Readiness is
   process-latched; zero does not clear it. No extra controller is needed.
4. Observe **`uint32_t altscreen_ui_session_generation(void)`** from the existing
   native bus timer and deliver its value with the bus connection generation.
   It performs one acquire atomic load: no lock, wait, file/OEM-memory read, or
   UI command. Zero means not ready; nonzero is a stable, never-reused process-local
   epoch after both successful stock Main110 SETUP and successful stock SessionStart,
   with the measured event client at receiver offset `0x2c0` nonnull. This is channel
   readiness, not phone-side layout acknowledgement. OEM-map readiness remains a
   separate gate. Main110/full teardown and `stopServer` withdraw readiness before
   waiting on stock lifecycle operations; failed/deferred cleanup stays withdrawn.
   Audio-only and Type111-only teardown preserve the live command-channel epoch.
   Captured operation epochs fence late completions, including reused addresses;
   older receivers cannot republish after a newer receiver is selected. A new
   channel lifetime after Main110 teardown gets a new epoch. Counter exhaustion
   or a full tracker fails closed instead of recycling epochs.
   Java requests the connection's cached layout URL once after **both** this
   readiness and OEM-map readiness, **before video-ready**, as well as handling existing
   generation-checked video/route/View/main-MMI triggers. Native code deliberately
   does not send startup showUI: waiting solely for video-ready would deadlock
   initial activation. The Java sender must coalesce this startup request with
   a nearby video-ready edge and keep stale connections fenced.
5. Add `/ramdisk/mmi-altscreen-displayable3.state` and
   `/ramdisk/altscreen-private111.keyframe-request` to relevant cleanup/private
   diagnostics if desired. The former contains ownership metadata, not card text.

### Exact staging/runtime inventory

- Mirror CLI: `--verbose`, optional diagnostic `--sink-test-grid`; no
  `--stream-supervisor`, version-query or build-info CLI. Normal startup logs
  `PHASE=BUILD id=carplay-private111-mu1316-source-v3.8-java-placement`.
- Build output directory `build/altscreen` contains `libcarplay_altscreen.so`,
  `carplay-alt111-mirror-display`, `SHA256SUMS`, `ELF_CHECKS.txt`,
  `QNX_LOAD_LAYOUT.json`, `SOURCES.sha256`. The source manifest hashes every file
  under `altscreen_native/` plus `scripts/build_altscreen.sh`, using repository-relative
  paths and the **same Linux-volume snapshot used by the compilers**, not a second
  host read. Packaging must verify it against the checkout before reusing binaries.
  **No `BUILD_INFO` file is generated**; packaging must
  generate its own metadata rather than reuse the binary-only release's identity.
- `/carplay111_h264`: POSIX SHM, version 1, magic `0x50313148`, 4 MiB ring.
  `/carplay111_decoded`: POSIX SHM, version 1, magic `0x50313146`, three
  2 MiB packed-tight NV12 slots. Both are owned by the receiver hook; mirror
  readers verify size and matching active writer PID/generation/stream cookie.
  Do not create, truncate or substitute these objects from a supervisor.
- `/tmp/altscreen-private111.stream-ready`: hook diagnostic marker, not a
  substitute for successful mirror EGL presentation.
- Ready defaults and launcher overrides:
  `ALT111_MIRROR_READY_FILE=/tmp/MMI-Cockpit-Carplay.mirror.ready`,
  `ALT111_MIRROR_BASE_READY_FILE=/tmp/mmi-mirror-basevideo.ready`,
  `ALT111_MIRROR_GATE_TOKEN_FILE=/tmp/MMI-Cockpit-Carplay.mirror.phone111.gate`,
  `ALT111_MIRROR_HOOK_LOG=/tmp/MMI-Cockpit-Carplay.altscreen_hook.log`.
  The existing phone-request log gate and guarded
  `ALT111_RECOVER_CURRENT_SESSION=1` path remain supported.
- The `/ramdisk/altscreen-private111.keyframe-request` path is fixed on both
  producer and reader. `ALT111_DISPLAYABLE_STATE_FILE` can override the
  ownership diagnostic snapshot only within `/ramdisk`.
- Fixed Type111 TCP port **6031** requires the boot-loaded `/etc/pf.conf`
  to contain `pass in quick on carplay0 proto tcp from any to any port = 6031 allow-opts`
  before the first terminal inbound `carplay0` block. The hook deliberately
  reads the real target path; filesystem prefixes belong only to installer/test
  fixtures. Missing static authorization retains upstream's bounded fallback,
  not an invented success signal. No firewall expectation was changed here.

## Build and verification

The QNX image lacks upstream's LLVM compiler. Build the derived local image once:

```sh
docker build -t mib2-altscreen-native:local -f altscreen_native/Dockerfile altscreen_native
bash scripts/build_altscreen.sh
```

On Git for Windows Bash set `MSYS_NO_PATHCONV=1` and `MSYS2_ARG_CONV_EXCL='*'`.
The build script itself uses a Linux Docker volume so 32-bit QNX binutils never
read Windows bind-mount inode numbers. Only the two verified artifacts and reports
are copied into `build/altscreen`; no existing staged SD snapshot is touched.

The hook uses LLVM/lld's freestanding ARMv7 softfp build and the upstream QNX
segment-layout validator. The mirror uses QNX GCC without a C++ runtime.
Exact hook exports, ARM EABI5/softfp, dependencies, absent emutls/compiler helpers
and forbidden native UI strings are checked. The mirror's two integer division
imports are actual exports of QNX6.5 `libc.so.3`, not a C++ runtime dependency.

Host checks run in the existing GLES image, with the repository at `/src`:

```sh
bash /src/altscreen_native/tests/run.sh
```

Tests exercise native UI rejection without external effects, matching transport
sessions and malformed decoded frames, atomic replacement failure, and real
offscreen GLES pixels at 1440x455 (1:1 clipping and NV12 color conversion).
They write fixtures only under `build/altscreen-host-tests`.

**Evidence limit:** source cross-build, ELF checks and host GLES tests are not
vehicle validation of QNX interposition, decoder scheduling, physical panel
occlusion, wireless adapters or iOS layout behavior. The local UI/placement
adaptations intentionally exclude upstream's competing policy; this is not a
claim that every upstream behavior or every vehicle fix was adopted unchanged.
