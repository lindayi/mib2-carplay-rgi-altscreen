## Intentional integration changes

- **Installed authority:** only `/mnt/app/root/carplay-altscreen/state` supplies
  `ACTIVE`, `ARMED*`, `FORCE_START`, `run_id` and `IAP2_PROFILE`. No SD or `/tmp`
  fallback can arm the hook. Missing/nonregular/symlink markers fail closed;
  a late installed-state mount can still become available. The independent
  `fullchain_probe` authorization check retains the same installed-root contract.
  Logging stays volatile, without automatic SD fallback.
- **Receiver transport:** the latest universal AUG22 dynamic relocation discovery,
  private Type111 setup/teardown serialization, retained command lifetimes,
  bounded deferred cleanup, stock OMX decoding, Screen linearization, and matching
  H264/decoded SHM contracts are imported. The dynamic redirect and QNX process-name
  transformations previously generated by upstream's build script are applied
  directly to the source. Known-profile direct-proxy builds are not produced.
- **One UI owner:** the initial integration's broad UI disable is superseded.
  Java selects URLs; the existing GPL bus command forwards an intent through
  `altscreen_queue_ui`, without its own direct showUI sender. The upstream
  retained-receiver bootstrap worker and command-completion path now form one
  receiver queue: no default startup URL, pending duplicate coalescing, three
  attempts per intent, late-callback fencing and no timer resend after success.
  Queue acceptance is not a phone acknowledgement. Actual completion seeds the
  stream monitor; Java readiness never fabricates `ui_event_state=2`.
  Upstream stopUI runs before teardown through the same command machinery,
  including a receiver with no private stream yet. Replacement Type111 resumes
  the same receiver's cached URL. Native wheel zoom and physical context/plane
  writers remain disabled; the existing project zoom handler remains sole owner.
- **Stream recovery:** restore the upstream monitor's actual updateViewArea,
  frame-baseline checking and bounded keyframe recovery. Extend its first-packet/
  zero-frame case instead of requiring the frame it is trying to recover.
  Remote ACKs do not establish recovered pixels; only fresh frame progress does.
  The two-probe budget replenishes only after sustained fresh progress; local
  admission failures have a separate three-failure bound. Existing PID/generation/
  cookie-bound consumer keyframes and tap ownership admission remain intact.
- **Geometry:** the mirror keeps the Type111 decoded source at 1440x542, with
  1:1 bottom clipping into the existing **1440x455** output. Internal offsets are
  zero; Java `AltScreenPlacement` alone moves displayable 3. The accepted HMI
  snapshot is read by workers independently of placement ownership. `/info`
  reads only a bounded nonblocking metadata cache. Before HMI replay, upstream's
  FULL default and both safe-area candidates are declared; accepted SMALL replay
  produces a real same-session updateViewArea, without waiting for a first frame.
  Map areas are FULL `(370,72,700,378)`, SMALL `(490,72,460,378)`; card areas are
  FULL `(300,72,840,378)`, SMALL `(470,72,500,378)`. The exec-time profile is
  mandatory before `/info`; missing/invalid values refuse the added declaration.
  The outer legacy RGI initial-area override automatically withdraws when the
  source queue export is present, before resolving CF or opening its old config.
  No position-triggered extra swap or native placement writer is introduced.
- **Source validity:** accepted decoded frames additionally require active matching
  H264 writer/generation/cookie both before and after copying. Missing/inactive
  transport cannot make old decoded memory look like a fresh session.
- **QNX filesystem:** the new display-ownership snapshot and consumer keyframe
  request use `/ramdisk` atomic replacement. Replacement failure preserves the
  previous snapshot; there is no `/tmp` or flash publication fallback.
- **Existing runtime:** ready/base-ready/gate/log defaults match the local launcher;
  its environment overrides remain supported. Existing supervisor recovery and
  SI receiver ownership are retained. No native USB reset or receiver restart is
  introduced. The upstream `--stream-supervisor` executable mode is not included.
- **Artwork:** the embedded logo asset and assembler inclusion are omitted.
  The source-built mirror stays blank until actual decoded video, rather than
  importing artwork or reporting logo pixels as video readiness.
- **Presentation telemetry:** remove upstream's duplicate first-frame submit:
  one accepted source frame makes one ordinary interposable `eglSwapBuffers`
  call; only success advances `presented_frames`. Ready markers follow the first
  successful video swap. The explicit sink-test-grid diagnostic is separate from
  normal video mode. `PHASE=RUN` retains generation, decoded/presented frame counts
  and measured presentation FPS; current-stream teardown retains the exact
  `PHASE=DIRECT111_TAP_STOP stream=` marker, distinct from stale-stream teardown.
  The health reader's four H264 counters remain at offsets `0x18` through `0x24`.

## Required parent integration

1. Stage **both** `build/altscreen/libcarplay_altscreen.so` and
   `build/altscreen/carplay-alt111-mirror-display`; regenerate package manifests.
   Include this directory's license texts and notice. Do not stage `stubs/`,
   `objects/` or a toolchain library. Do not apply the old binary-only 30-fps
   patcher to these already source-built artifacts.
2. Preserve receiver preload order: local RGI hook before AltScreen hook.
   Preserve the isolated mirror-only mascot preload and existing settings,
   cards, VC panel and mascot `/ramdisk` contracts.
3. Forward `CMD_OEM_MAP_READY` (`0x0119`) to
   **`void altscreen_oem_map_ready(int ready)`**. The read-only export
   **`int alt_oem_map_startup_ready(void)`** is not the setter. Readiness is
   process-latched; zero does not clear it. No extra controller is needed.
4. Observe **`uint32_t altscreen_ui_session_generation(void)`** from the existing
   native bus timer. `EVT_ALT_SESSION` (`0x0031`) is now **exactly eight binary
   big-endian bytes: uint32 epoch, uint32 receiver PID (`getpid()`)**, including
   unavailable epoch zero. Deliver the pair with the bus connection generation.
   It performs one acquire atomic load: no lock, wait, file/OEM-memory read, or
   UI command. Zero means not ready; nonzero is a stable, never-reused process-local
   epoch after both successful stock Main110 SETUP and successful stock SessionStart,
   with the measured event client at receiver offset `0x2c0` nonnull. This is channel
   readiness, not phone-side layout acknowledgement. OEM-map readiness remains a
   separate gate. Main110/full teardown and `stopServer` withdraw readiness before
   waiting on stock lifecycle operations; failed/deferred cleanup stays withdrawn.
   Audio-only and Type111-only teardown preserve the live command-channel epoch.
   Captured operation epochs fence late completions, including reused addresses;
   older receivers cannot republish after a newer receiver is selected. A new
   channel lifetime after Main110 teardown gets a new epoch. After an admitted
   per-stream stock teardown returns, retire the old UI slot even if `out_done`
   is zero: the receiver need not be destroyed. A full teardown with `out_done=0`,
   refused admission or cleanup failure retains its closing fence. Never reopen
   a closing slot in `alt_ui_session_begin`; fresh successful SETUP/START and
   the event client must establish readiness again. The host
   `main110_lifecycle_test.py` compiles the production wrappers and session guards
   with explicit stock/CF/private111 fixtures, including a per-stream `out_done=0`.
   It reproduces the integration defect and checks stale/reentrant callbacks,
   failed cleanup, full teardown, and audio/Type111 isolation. Counter exhaustion
   or a full tracker fails closed instead of recycling epochs.
   Java requests the connection's cached layout URL once after **both** this
   readiness and OEM-map readiness, **before video-ready**, as well as handling existing
   generation-checked video/route/View/main-MMI triggers. Native code deliberately
   does not invent a startup URL: waiting solely for video-ready would deadlock
   initial activation. The Java sender must coalesce this startup request with
   a nearby video-ready edge and keep stale connections fenced.
5. Add `/ramdisk/mmi-altscreen-displayable3.state` and
   `/ramdisk/altscreen-private111.keyframe-request` to relevant cleanup/private
   diagnostics if desired. The former contains ownership metadata, not card text.
6. Before **exec of each receiver**, project validated session preferences into
   **`ALTSCREEN_PHONE_PROFILE=map`** or **`ALTSCREEN_PHONE_PROFILE=card`**.
   With the format-6 layout IDs, card is `{0,1,4}` and map is `{2,3}`. The native
   hook does not read preferences or an upstream `card.enabled` marker. Never
   silently select a profile when validation fails. This is a connection-level
   geometry choice, not a live environment toggle. Card left/top/right may
   update the selected URL live within an existing card profile.
7. **`int altscreen_queue_ui(const char *url, uint32_t native_epoch)`** copies a
   bounded ASCII cluster URL, returning 0 for queued/coalesced intent and -1 for
   refusal. `map` profile accepts exactly `maps:/car/instrumentcluster/map`;
   `card` accepts exactly `maps:/car/instrumentcluster`. Either base may have an
   optional `?` query; the opposite family, extra subpaths and suffixes are
   rejected before queuing. This defends the exec-time geometry contract and
   does not replace the parent's PID-bound initial-selection alignment.
   It performs metadata work only. The current raw `CMD_ALT_UICTX`
   payload is unchanged; its RGI handler supplies the source epoch. Java must
   retain bus/connection/module generation checks before enqueue and actual
   socket send: a raw URL contains no sender epoch and cannot independently
   identify a delayed packet from an old Java connection. Do not add another
   direct showUI sender or treat the bridge return value as remote completion.
8. Publish **`/ramdisk/mmi-mirror-hmi.state`** atomically from the Java worker,
   using upstream keys plus a native-epoch fence:

   ```text
   view=FULL
   layout_name=LayoutMIB2HighB9Sport
   small_stage_dx=-476
   small_stage_dy=0
   receiver_epoch=123
   receiver_pid=456
   expiry_ms=1792341001000
   ```

   `view` is exactly FULL or SMALL from accepted stock Fct54 state, including
   replay; `layout_name` is the actual layout class. `receiver_epoch` is the
   current nonzero EVT_ALT_SESSION epoch. `receiver_pid` must be the PID from
   that same eight-byte event, not a separately reread wrapper PID file.
   `expiry_ms` is unsigned decimal Unix epoch milliseconds, compatible with
   Java `System.currentTimeMillis()` and native `CLOCK_REALTIME`.
   All seven keys are required exactly once; unknown, duplicate, oversized,
   nondecimal or overflowing fields fail closed.
   Accept only **`0 < expiry_ms - now_ms <= ALT_LOCAL_HMI_LEASE_MS`**.
   `integration.h` defines **`ALT_LOCAL_HMI_LEASE_MS=1500u`**, shared by all
   three native reader/cache checks for Java/C parity validation.
   Publish a complete atomic
   refresh at most every 500 ms. Both the worker reader and `/info` metadata
   cache enforce PID, epoch and expiry; cached data expires even if its reader
   stalls. Before/after identity checks reject process-restart epoch collisions.
   Withdraw on disconnect/unknown ownership; expired/malformed status also
   withdraws eligibility. Retain matching-owner startup/teardown cleanup, but
   correctness no longer depends on cleanup defeating an old producer.
   No `/tmp` fallback. Workers sample
   at the existing 100 ms cadence; stock callbacks and `/info` do not open files.
   Java remains the sole physical writer: upstream card Sport SMALL uses **-445**
   instead of map-profile **-476**; preserve the selected profile until reconnect.
   The native hook's calculated physical rectangles are diagnostics, not writes.
   The full selected URL must preserve cached sign/ETA/profile and live card
   position across route/View/manual reapply. Phone sign is phone pixels only.

### Exact staging/runtime inventory

- Mirror CLI: `--verbose`, optional diagnostic `--sink-test-grid`; no
  `--stream-supervisor`, version-query or build-info CLI. Normal startup logs
  `PHASE=BUILD id=carplay-private111-mu1316-source-v3.8-java-placement`.
- Build output directory `build/altscreen` contains `libcarplay_altscreen.so`,
  `carplay-alt111-mirror-display`, `SHA256SUMS`, `ELF_CHECKS.txt`,
  `QNX_LOAD_LAYOUT.json`, `SOURCES.sha256`. The source manifest hashes every file
  under `altscreen_native/` plus `scripts/build_altscreen.sh`, using repository-relative
  paths and the **same Linux-volume snapshot used by the compilers**, not a second
  host read. Packaging must verify it against the checkout before reusing binaries.
  **No `BUILD_INFO` file is generated**; packaging must
  generate its own metadata rather than reuse the binary-only release's identity.
- `/carplay111_h264`: POSIX SHM, version 1, magic `0x50313148`, 4 MiB ring.
  `/carplay111_decoded`: POSIX SHM, version 1, magic `0x50313146`, three
  2 MiB packed-tight NV12 slots. Both are owned by the receiver hook; mirror
  readers verify size and matching active writer PID/generation/stream cookie.
  Do not create, truncate or substitute these objects from a supervisor.
- `/tmp/altscreen-private111.stream-ready`: hook diagnostic marker, not a
  substitute for successful mirror EGL presentation.
- Ready defaults and launcher overrides:
  `ALT111_MIRROR_READY_FILE=/tmp/MMI-Cockpit-Carplay.mirror.ready`,
  `ALT111_MIRROR_BASE_READY_FILE=/tmp/mmi-mirror-basevideo.ready`,
  `ALT111_MIRROR_GATE_TOKEN_FILE=/tmp/MMI-Cockpit-Carplay.mirror.phone111.gate`,
  `ALT111_MIRROR_HOOK_LOG=/tmp/MMI-Cockpit-Carplay.altscreen_hook.log`.
  The existing phone-request log gate and guarded
  `ALT111_RECOVER_CURRENT_SESSION=1` path remain supported.
- The `/ramdisk/altscreen-private111.keyframe-request` path is fixed on both
  producer and reader. `ALT111_DISPLAYABLE_STATE_FILE` can override the
  ownership diagnostic snapshot only within `/ramdisk`.
- Fixed Type111 TCP port **6031** requires the boot-loaded `/etc/pf.conf`
  to contain `pass in quick on carplay0 proto tcp from any to any port = 6031 allow-opts`
  before the first terminal inbound `carplay0` block. The hook deliberately
  reads the real target path; filesystem prefixes belong only to installer/test
  fixtures. Missing static authorization retains upstream's bounded fallback,
  not an invented success signal. No firewall expectation was changed here.

## Build and verification

The QNX image lacks upstream's LLVM compiler. Build the derived local image once:

```sh
docker build -t mib2-altscreen-native:local -f altscreen_native/Dockerfile altscreen_native
bash scripts/build_altscreen.sh
```

On Git for Windows Bash set `MSYS_NO_PATHCONV=1` and `MSYS2_ARG_CONV_EXCL='*'`.
The build script itself uses a Linux Docker volume so 32-bit QNX binutils never
read Windows bind-mount inode numbers. Only the two verified artifacts and reports
are copied into `build/altscreen`; no existing staged SD snapshot is touched.

The hook uses LLVM/lld's freestanding ARMv7 softfp build and the upstream QNX
segment-layout validator. The mirror uses QNX GCC without a C++ runtime.
Exact hook exports, ARM EABI5/softfp, dependencies, absent emutls/compiler helpers
and forbidden duplicate-zoom/separate-preference strings are checked. The mirror's two integer division
imports are actual exports of QNX6.5 `libc.so.3`, not a C++ runtime dependency.

Run host checks from the repository with the existing GLES image:

```sh
bash altscreen_native/tests/run_docker.sh
```

The helper defaults to `mib2-mascot-video-test` (`ALTSCREEN_TEST_IMAGE` overrides
it), mounts sources read-only at `/src`, and mounts an automatically removed
anonymous **Linux volume** at `/src/build/altscreen-host-tests`. The QNX build
image is not the host-test image: it lacks host `g++` and EGL/GLES dependencies.
On a native Linux filesystem with those dependencies, `tests/run.sh` also works
directly. Do not run atomic-publication fixtures on a Windows Docker bind mount:
host investigation observed `fopen` returning ENOENT immediately after successful
replacement there. This is not evidence of a QNX `/ramdisk` failure.

The ownership fixture publishes and verifies initial geometry before starting
its concurrent queue worker. `/info` intentionally reads a nonblocking cache;
requiring an exact initial index while the fixture's 1 ms worker owns that cache
was an invalid timing assumption, independently reproduced on a Linux volume.
The worker still runs for all queue/coalescing/completion/teardown assertions.
Runtime identity, epoch, PID, lease, fail-closed behavior and geometry assertions
are unchanged. The corrected complete host suite and 30 additional ownership
fixture runs passed on the Linux volume.

Tests exercise real showUI/stopUI/updateViewArea dictionaries and completion,
pending coalescing, stale sessions, replacement streams, bounded remote failures,
zero-frame recovery through the native stream helper, initial FULL/SMALL and
both safe-area profiles, matching transport sessions and malformed decoded frames,
atomic replacement failure, and real
offscreen GLES pixels at 1440x455 (1:1 clipping and NV12 color conversion).
They write fixtures only under `build/altscreen-host-tests`.
The UI/completion, PID/epoch/realtime-lease and zero-frame fixtures run under ASan/UBSan. The real GPL
bus bridge and legacy-area isolation fixtures run from the same host suite.

**Evidence limit:** source cross-build, ELF checks and host GLES tests are not
vehicle validation of QNX interposition, decoder scheduling, physical panel
occlusion, wireless adapters or iOS layout behavior. These host fixtures replace
OEM CF/transport and do not prove the phone honors the requests. The local
placement/zoom adapters preserve single ownership; this is not a
claim that every upstream behavior or every vehicle fix was adopted unchanged.
